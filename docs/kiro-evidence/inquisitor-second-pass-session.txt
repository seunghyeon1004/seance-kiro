## New CONFIRMED findings

### HIGH — MCP can make network requests through a local partial clone

**Files:** `src/mcp/repo.ts:49-50`, `src/mcp/tools.ts:185-189`, `src/evidence/git.ts:88-95`

`resolveLocalRepo` refuses a remote argument, but it accepts a local promisor/partial clone. `seance_summon` then runs `blame`, `log`, and `show` without `GIT_NO_LAZY_FETCH=1`. Missing objects cause Git to contact the remote stored in `.git/config`. The same applies to `seance_haunting_map`.

**Concrete input:** Pass the path of a local `--filter=blob:none` clone whose historical blob is absent and whose promisor remote points to an attacker-controlled HTTP or SSH endpoint. Summoning that historical line causes Git to fetch the object. Git may also invoke configured transport or credential helpers.

This contradicts the MCP server’s no-network boundary. `test/mcp/imports.test.ts` cannot detect subprocess-initiated network access.

**Smallest fix:** Set `GIT_NO_LAZY_FETCH=1` in `src/mcp/server.ts` before the dynamic import, so every Git subprocess in the dedicated MCP process inherits it. Also cover programmatic server construction or document that only the entry point enforces the boundary.

**Failing test:** Start the stdio MCP server against a partial clone with an absent object and a controlled HTTP remote. Call `seance_summon`; assert the HTTP server receives zero requests and the tool returns a fixed Git error.

### MEDIUM — Invisible controls outside `IGNORABLE_RANGES` still hide authors and years

**File:** `src/ghost/verifier.ts:93-127`

U+1BCA0–U+1BCA3 and U+1D173–U+1D17A are default-ignorable format controls but are absent from `IGNORABLE_RANGES`.

**Concrete input:** The ledger contains authors `Alice` and `Bob`; cite Bob’s 2020 commit with the valid quote `supported phrase`:

```json
{
  "kind": "memory",
  "text": "A𛲠lice wrote this in 20𝅳24.",
  "citations": [{ "sha7": "bbbbbbb", "quote": "supported phrase" }]
}
```

Here the displayed controls are U+1BCA0 and U+1D173. The current verifier accepts the claim. A conforming renderer normally hides both controls, leaving “Alice … 2024.”

Cyrillic `Аlice` and lowercase `alice` also remain accepted. Cyrillic homoglyphs matter because they can be visually indistinguishable. Lowercase matching is an explicit documented limit but still permits a believable unsupported attribution.

**Smallest fix:** Extend the fixed ranges to the complete Unicode `Default_Ignorable_Code_Point` set supported by Node 20, while retaining raw quote comparison. Do not case-fold unless common-word author false positives are separately addressed.

**Failing test:** Add the claim above to `test/ghost/verifier.unicode.test.ts`; expect rejection for unsupported author `Alice` and year `2024`. Add a property that inserts every code point in the complete default-ignorable set into a detected author/year.

### MEDIUM — A forwarded proxy error can still replay an accepted model request

**File:** `public/app.js:107-109,158-163`

The browser assumes every non-JSON 502/503/504 came from a proxy before the request reached the server. A proxy can generate the same response after the server accepted the request but lost or rejected its response.

**Concrete input:** The proxy forwards `/api/ask`; the model call completes; the upstream connection then fails; the proxy returns an HTML 502. The page waits two seconds and submits the same ask again. Both requests consume model calls.

**Smallest fix:** Never retry `/api/ask` or `/api/exorcise` automatically after any response that does not prove the request was rejected before forwarding. The alternative is a client idempotency key with server-side response caching.

**Failing test:** Change the existing 502 test so its proxy calls `await req.forward()` before returning HTML 502. Assert one browser attempt and one model invocation. It currently produces two.
