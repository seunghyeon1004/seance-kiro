## CONFIRMED (they follow from the rules as written)

**C1. Broken: the hero candle overflows its box at 768, 390 and 320 px (every state).**
- **Cause:** `styles.css:872` shrinks `.candle` to 3rem × 7.5rem (120 px). `.wax` (`:290`, 10.5rem) and `.wick` (`:302`, 1.6rem) are not scaled, so 193.6 px of content sits in a 120 px grid with `align-content: end` (`:270`).
- **What the user sees:** the content spills about 74 px upward (that direction is S-level, see S1). The flame (absolute, `top: 4%`) lands on the middle of the wax. The wick and the top 20 px of wax paint into the header, because `main` and `.bar` both have `z-index: 1` (`:41`) and `main` comes later.
  - At 390 and 320, the dark 3 px wick crosses the letters "St" of the wrapped "Still the candles" button, and the wax covers its bottom edge and the header rule.
  - At 768, the wick cuts through the "Séance" wordmark.
- **Fix:** in the 60rem block, add `.candle .wax { height: 4.9rem } .candle .wick { height: 0.75rem }` and `.candle-stage { pointer-events: none; }`.

**C2. Ugly: the guide steps lose their numbers (all viewports, states b–d).**
- **Cause:** `.guide-steps > li { display: grid }` (`:1102`). The `li` is no longer `list-item`, so no markers are drawn, but `padding-inline-start: 24px` (`:1096`) remains.
- **What the user sees:** "Try it in three clicks" sits over three unnumbered, indented items.
- **Fix:** `.guide-steps { list-style: none; padding-inline-start: 0; counter-reset: g } .guide-steps > li { counter-increment: g } .guide-title::before { content: counter(g) ". " }`.

**C3. Ugly: `.field.wide` overrides `.actions` and `.token` (above 640 px).**
- **Cause:** `.field.wide { grid-column: span 2 }` (`:133`, specificity 0,2,0) beats `.token { grid-column: 1/-1 }` (`:193`) and `.actions { grid-column: span 4 }` (`:208`), both 0,1,0.
- **What the user sees:** the token disclosure sits in columns 3–4 next to From/To line, and its summary text is 8 px lower than those labels because of its padding. The Summon row is half width (338 px at 1280, 294 at 1024). "Found N commits…" and the 80-character "Cloning from GitHub…" text wrap under the button into 2–3 lines.
- **Fix:** `.summon .actions, .summon .token { grid-column: 1 / -1; }`. This adds about 50 px, and the fold still passes (see the hero section).

**C4. Ugly: after a summon, "The line in question" is scrolled off the top (1280 and 1024).**
- **Cause:** `app.js:401` scrolls `#h-guide` to the top, and `scroll-padding-top: 96px` (base.css) puts it at y=96. The guide heading is about 236 px below the top of `#seance` (talk head 74, counter 17, `#ward-limit` 43, gaps, guide padding).
- **What the user sees:** `#seance` starts at y ≈ −140. The source heading and `#source-meta` are above the viewport, and about 13 px of the code box shows.
- **Fix:** above 60rem, scroll `$('seance')` with `block: 'start'` and keep `h.focus({ preventScroll: true })`. The guide heading then lands at y ≈ 330. Below 60rem, keep the current target.

**C5. Ugly: the verified counter scrolls out of view after the first answer (all viewports, state c).**
- **Rule broken:** ui-spooky.md says the "N of M claims verified" counter is always visible while a séance is active.
- **Cause:** `#verified-counter` (index.html:175, `styles.css:805`) is a plain paragraph at the top of `.talk`.
- **Fix:** `.verified-counter { position: sticky; top: 0; z-index: var(--z-sticky); background: var(--color-paper); padding-block: var(--space-xs) } .verified-counter:empty { position: static; }`.

**C6. Broken for sighted users: errors appear far from the control that failed (state f, after a few turns).**
- **Guide buttons:** exorcise, plant and possess errors are appended at the end of `#log` (`app.js:1221`, `1260`, `1455`), and the status next to the button is cleared. The buttons sit in the guide above the log, so after a few turns nothing changes on screen near the button. Only screen readers hear the alert.
- **Map:** `#map-status` and `#map-err` come after every tile (index.html:322–323). Clicking "Summon here" on an early tile shows its progress and its error possibly several screens below.
- **Fix:** move those two map elements to just after `#map-meta`. Write guide errors into an `.err` paragraph placed after `#ward-status` or `#exorcise-status`.

**C7. Ugly, and a rule violation: a card inside a card in the exorcism's "Do not touch" list (state d).**

**C8. Ugly: the header with three children (all viewports).**

**C12. Minor: empty space reserved in state b.**

- The empty `#map-status` keeps 19.6 + 16 px.

**C14. Minor: one undersized target.** `.ledger details summary` is 21.7 px tall. It passes WCAG 2.5.8 through the spacing exception but is fiddly on phones. Fix: `padding-block: var(--space-2xs)`.

## SUSPECTED (depends on browser behaviour)

- **S1.** The C1 overflow goes up, not down. This assumes Chrome and Firefox treat grid `align-content` overflow as unsafe. If they don't, the wax overlaps the h1 by about 20 px instead.
- **S2. The plant and token disclosures as grid containers.** Chrome 131+ wraps non-summary children in `::details-content`; older Chrome and Safari ignore grid on `details`. Either way, `gap` does not reach the open plant form, so help text, label, inputs, row, error and button stack with no spacing. `.plant #plant-btn { justify-self }` (`:636`) does nothing, and a closed `details` gets an extra 12 px under its summary. Fix: wrap the content in `<div class="plant-body">` with its own grid and gap.
- **S3. A cite click jerks the page.** `row.scrollIntoView({ block: 'center' })` (`app.js:569`) can scroll the page even when the row is already visible in the stuck crypt. The crypt stays put and the answer being read moves. Fix: `block: 'nearest'`.
- **S4. The hidden lit note can lengthen the page.** The `.lit-note` span (`app.js:547`) is positioned absolutely, and its containing block is `.crypt`, not the ledger's scroll box, so `overflow: auto` does not clip it. A lit row deep in a long ledger can add blank scroll height to the page. Fix: `.ledger li { position: relative }`.
- **S5. Line-number markers cross the source box's left border.** `.source-lines` (`:1066`) has 40 px of left padding. Markers like "1234." need about 50 px at 14 px monospace, and 3-digit ones touch the border. Fix: `padding-inline-start: calc(6ch + var(--space-sm))`.
- **S6. The planchette can cover part of the first ledger row.** `.planchette` (`:403`) has no `pointer-events: none`. Pointing down, it reaches about 84 px from the crypt top, past where the ledger starts (about 76 px) when `#crypt-shallow` is hidden. It can cover the top-right 8 px of the first row. Fix: `pointer-events: none`.
- **S7. Unisolated names.** Names inserted as plain text in `#ghost-name`, `.map-who`, `.map-group h3` and `.map-name` are outside the R11.8 isolation list. A name with an unterminated U+202E would reverse the fixed text after it. This matters only if the server leaves bidi controls in. Fix: wrap each name in `<bdi>`.

## Parts that are sound

- **The `minmax(0, 1fr)` list (`:1172–1200`):** nothing on it needed more than one column.
- **Media-query rules:** no 60rem or 40rem rule is overridden by a later rule of equal specificity. I checked `.crypt`, `.candle`, `.candle-stage`, `.ledger`, `.btn`, `.claim` and `.signals li`.
- **`.status:empty { position: absolute }`:** the empty spans are zero-width inside positioned parents and cover nothing. The HTML spans contain no whitespace, so `:empty` matches.
- **Buttons at 40rem:** `.btn` goes 100% wide and `.btn.small` stays auto, as intended. Only Summon, Ask and Copy go full width. The map's "Summon here" buttons are not full width on phones, but they are 40 px tall.
- **`[hidden]`:** the `!important` rule beats every display rule.
- **Sticky crypt:**
  - `align-self: stretch` on `.seance-col` plus the flex column lets it stick.
  - It only ever moves down from its normal position, so it never overlaps `#source`.
  - Stuck, it is about 620–690 px tall, which fits both desktop viewports.
- **Planchette vs heading:** the 5rem right padding on `.crypt-head` keeps the heading and `#crypt-shallow` clear, rotated or not.
- **Map fog:** the `::before` layer (`z-index: -1` under `isolation: isolate`) paints above the tile background and below the text. Contrast stays at 5.45:1 or better.
- **Map grid:** 4, 3, 2, 1 and 1 columns at the five widths, with no overflow. Long paths and long names wrap everywhere.
- **320 px:** no horizontal overflow found. The longest chip (about 272 px) wraps inside the 264 px guide column. The signals bar keeps about 130 px.
- **Focus rings:** visible on all the new controls, and none are clipped. The ledger rows draw theirs inside the scroll box.
- **IDs:** every id that app.js reads exists in index.html, and there are no duplicate static ids. `ledger-item-<sha7>` would only duplicate if two commits shared a short hash.
