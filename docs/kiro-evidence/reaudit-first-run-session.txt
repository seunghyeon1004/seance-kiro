## 2. The judge's path on the hosted demo (Render free plan, container asleep)

The same opening applies to all three runs.
- **Opening the URL.** The page is served by the sleeping container, so nothing from Séance can appear until it boots. The judge gets a blank tab or Render's own waiting page for Render's boot time plus `npm start`: two bash scripts making about 17 git commits, then tsx compiling at load. This is SUSPECTED to take 30–90 s on 0.1 CPU. `wake()` only helps a tab that was already open.
- **The page loads.** The hero shows the headline, the 32-word lede, a form prefilled with `crypt`, `legacy/tax.js`, lines 7–7, and one orange **Summon** button.

### A. The model works
1. **Click 1, Summon.** The status says "Gathering evidence…", which is quick for a sample. The page scrolls to "Try it in three clicks". The left column shows the line, then the crypt (2 commits). The right column shows the guide. The haunting map appears below.
2. **Click 2, a chip** ("Why is there a three second wait here?"). The status says "The ghost stirs…" with no timer for 5–30 s (SUSPECTED). Then cited claims appear, labelled "Citations verified", with "The words the ward found" under each. **2 clicks to a cited answer.**
3. **Click 2 instead, "Invent a citation".** The struck claim appears at once with "The ward refused it: Commit deadbee is not in the ledger." **2 clicks to a refused claim.**
4. **Exorcism.** The status says "Performing exorcism…" for up to 90 s, or about 180 s if the model's output fails to parse and the retry also runs long. There is no timer (SUSPECTED). "This can take a minute" can be wrong.

### B. No model key
1. **On load.** Health returns `model:false`, so a 24-word `#model-note` appears under the form: "The model is resting… the ward demo works as always." The judge has not seen any "ward demo" yet.
2. **Click 1, Summon.** Same as run A.
3. **Click 2, a chip.** A recorded answer appears instantly, labelled "A recorded answer (the model is resting). The ward checked it again just now." **2 clicks.**
4. **Ward presets.** Same as run A. **2 clicks to a refused claim.**
5. **Own question.** It gets a 503: "The ghost cannot speak on this server (no model key). The crypt and the ward still work." This is clear.
6. **Dead end (CONFIRMED).** "Summon here" on any map tile, including the "You are here" tile for `legacy/tax.js`, makes a whole-file session. That session is no longer the sample's default range, so `recordingTargetFor` returns null and every chip in it fails with the no-key message. "Summon here" also rewrites the hero fields to the whole-file range. Pressing Summon again does not bring back line 7, so the recordings stay off until the judge types 7 and 7 again.

### C. Daily cap used up (model configured)
1. **On load.** Health says `model:true`, so no note appears.
2. **Chips.** Recorded answers, with the same "model is resting" label (server.ts:689 plus the `onDaily` hook). **2 clicks.**
3. **Ward presets and exorcism.** Unaffected. The recorded plan is served for the default range.
4. **Own question.** It gets a 429: "The séance is closed for tonight. The spirits will answer again tomorrow. Try again in about N hours." Nothing says the ward and the chips still work. In Europe this text appears in the afternoon.
5. **Side effect (CONFIRMED in code, SUSPECTED on Render).** The cap lives in memory (ratelimit.ts), and so do the sessions. Each time the free container sleeps and wakes, the cap starts again from zero. In practice it is a cap per waking period, not per day.
