```typescript
const SummonRequestSchema = z
  .object({
    repoUrl: z
      .string()
      .min(1)
      .refine(
        (url) => {
          // If it looks like a URL, it must be a GitHub URL
          if (url.startsWith('http://') || url.startsWith('https://')) {
            return GITHUB_URL_RE.test(url);
          }
          return true;
        },
        { message: 'remote URLs must be https://github.com/<owner>/<repo>' },
      ),
    file: z.string().min(1),
    startLine: z.number().int().min(1),
    endLine: z.number().int().min(1),
    githubToken: z.string().optional(),
  })
  .superRefine((val, ctx) => {
    // R9.2: end must be >= start
    if (val.endLine < val.startLine) {
      ctx.addIssue({
        code: z.ZodIssueCode.custom,
        path: ['endLine'],
        message: `endLine (${val.endLine}) must be >= startLine (${val.startLine})`,
      });
    }
  });
```

---

**Why this is the smallest correct fix:**

- `LedgerInputSchema` already has this exact check. The shapes aren't identical (it also validates path traversal, max-range, and the full GitHub URL pattern), so I can't just swap `SummonRequestSchema` out for it wholesale without changing the existing URL validation message — which would break the test at line "returns 400 + VALIDATION_ERROR for a non-GitHub URL". A targeted `.superRefine` on `SummonRequestSchema` is the minimal, non-breaking change.
- The error message `endLine (2) must be >= startLine (9)` is the same wording `LedgerInputSchema` uses, keeping the two schemas consistent.
- `buildLedger` is never called — the `safeParse` rejection returns before the `try` block, so no git layer involvement.
