Goal: make the page's promise true: nothing reaches the user marked verified unless a deterministic check found its evidence, even when the repository is hostile and even when the model fully obeys an injected instruction. The verifier may only become stricter. Never loosen an existing check.

Decisions already made (write them as requirements, with the reasoning in "Why"):
A. Quotes are mandatory. A memory or speculation citation without a quote is rejected. Quote minimum length 8 characters after trimming; maximum 500. The schema, the tool JSON schema sent to the model and the prompt all say so. Each quote is checked against one field at a time (subject, body, or the hunk as sent to the browser), not against a joined string. The API returns the verified quotes and the UI shows them under each claim as "the words the ward found", so the reader can compare the ghost's sentence with the evidence. The limit is stated honestly: the ward proves the citation and the quote, it cannot prove a paraphrase.
B. Author and date invariant from evidence-rules.md is enforced: a claim whose text contains a four-digit year 1970-2099 that is neither the year of a cited item's date nor present in a cited item's text is rejected; a claim whose text names a ledger author (full name, case-sensitive, whole word) who is neither the author of a cited item nor named in a cited item's text is rejected. Reasons are plain sentences. Names not in the ledger cannot be caught: say so.
C. Silence claims are not "verified". They need no citation, but they are reported in their own bucket/flag so the UI labels them "The record is silent (the ghost's words, not checked)" and they are not counted in "N of M claims verified". Their text is capped at 300 characters. Keep VerifierResult.score semantics defined precisely.
D. Ambiguous short SHAs: if two ledger items share a shortSha, a citation of it is rejected as ambiguous.
E. Prompt construction: the rules go in the Anthropic `system` parameter; ledger text goes in the user turn with `&`, `<`, `>` and `"` escaped in every interpolated field (author, date, subject, body, hunk); the author name never appears in the system text; an evidence item flagged suspiciousMessage carries a visible marker attribute. buildPrompt stays pure and deterministic. Recorded fixtures are keyed by prompt hash, so they must be re-recorded from a real model call (scripts/record-plan-fixture.ts), never hand-edited.
F. isSuspicious gets a broader, still fixed-string needle list, and the flag is finally used: the summon response already carries it; the UI marks such ledger rows ("This commit tries to give the ghost orders") and marks any claim that cites one.
G. Exorcism plan: a step or do-not-touch entry with zero verified claims is not shown as part of the plan (it is returned in a separate `dropped` list with the reason); free-text fields (summary, description, rationale, characterization tests) are labelled in the UI as the model's words, not checked.
H. A hostile sample repository, `possessed`, built by scripts/make-possessed.sh next to the crypt (deterministic dates and authors, fictional people): commits whose messages order the ghost to say a line is safe to delete and to cite without quotes; an author name that reads like a system rule; a body that closes the evidence block and forges a new one attributed to another commit's sha7; an instruction to answer with a silence claim carrying a false statement. It is selectable in the UI as a second sample ("possessed") exactly like "crypt".
I. Adversarial tests with a scripted worst-case model (a fake AnthropicClient that does exactly what each injected instruction says): for every attack in H, the pipeline (buildLedger on the real possessed repo -> buildPrompt -> askGhost with the fake client -> verify -> the /api/ask response) never returns the attacker's sentence in `verified`. Plus property tests: for arbitrary claim text and any ledger, a claim without a quote that is a substring of a cited field is never verified.
J. Input and abuse hardening: /api/summon applies validateLedgerInput (path traversal, absolute path, 500-line cap) and returns a generic message for git failures (no command lines, temp paths or stderr to the client; details logged server-side); a request body limit of 64 KB on all POST routes; caps in the schema (at most 50 claims, 10 citations per claim); /api/summon gets its own per-client limit (separate limiter instance, default 20 per 10 minutes, env SUMMON_RATE_LIMIT_MAX) and at most 3 concurrent remote clones (503 when full); the session map is capped (default 500, oldest evicted); /api/ward gets a per-client limit too (default 60 per 10 minutes) but must never consume the model's daily cap. The existing model limiter's behaviour and tests must not change. The X-Forwarded-For question (leftmost entry is spoofable) is recorded as an open risk in design.md, not changed, because the hosting proxy chain is not verified.
K. Out of scope: binding paraphrase to quote with a second model; sandboxing git; changing the clone depth.

Requirements must be testable one by one. In design.md include: the exact new/changed Zod schemas and TypeScript types; the new verifier algorithm in numbered steps; the reason strings; the prompt layout; the API response changes (field by field, backward compatible where possible); the UI changes with element ids and the copy text, following .kiro/steering/ui-spooky.md (no colour-only signalling; tokens only); the possessed repo's commit list; a table mapping each audit finding (C1-C7, P1, R1-R3) to requirement ids; and 8 to 12 correctness properties. Do not write tasks.md. Do not modify any file outside .kiro/specs/ward-hardening/.

These choices go beyond what you specified, or settle something you left open:

- **Malformed claims are struck, not fatal.** If the schema alone made quotes mandatory, a model that obeyed "cite without quotes" would make the whole answer fail with a 503. Instead the model's answer is checked only at the outer level, and the verifier checks each claim and strikes a bad one with a reason.
- **Plan transport.** The plan currently travels inside a fake answer citing `0000000` with no quote, which mandatory quotes would break. `askPlan` now returns the raw plan instead.
- **Score.** `score = verified / (verified + rejected + silent)`. This matches the steering file ("total includes silence"), while "N of M" counts only checked claims. It replaces ghost-verifier R3.5.
- **Hunk.** The prompt sends the same first 4,000 characters of the hunk that the browser and the verifier use, so a valid quote is always one the reader can see.
- **Extra attack A5.** I added a fifth attack (wrong person and year, with a real quote) so the author and year checks have an end-to-end test.
- **Self-quoting limit.** If an obedient model quotes the injected sentence from its own commit, that claim is verified, because the commit really says it. The design records this as a known limit with its own test, and shows the suspicious-commit label on such claims. Rejecting every claim that cites only flagged commits would be stricter; I left that as a product decision for you.
- **"Only stricter" test.** A property test checks every new verdict against a frozen copy of the current verifier (commit `d738258`).
- **Steering update needed.** `evidence-rules.md` still says `{ sha7, quote? }`, and I couldn't change it in this session. It's listed as a follow-up (N7).
