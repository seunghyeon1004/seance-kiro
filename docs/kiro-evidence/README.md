## Not proven

- Context7 documentation was never actually fetched through the power (MCP server not connected).
- The IDE save hooks (`PostFileSave`) have not been seen firing. The CLI agent hooks in `warden.json` have: `postToolUse` and `stop` on 3.1.0 V2, and all three, `agentSpawn` included, on 3.2.0 V3.
- Kiro Crew ran with `--approval yolo` in an isolated home; its dashboard was not opened.
- The page was looked at in a browser only once, at the very end and by hand (headless Chromium: screenshots at 1280, 768, 390 and 320 px, an overflow measurement, console errors). Keyboard focus, reduced motion, forced colours and the wake-up retry against a restarted server were not checked in a browser; they rest on jsdom tests and on reading the CSS.
- In the V3 engine, non-interactive runs deny shell and MCP tool calls unless `--trust-all-tools` is passed, whatever the agent file's `allowedTools` and `permissions` say (seen with the inquisitor and the archaeologist). The V2 engine honours `allowedTools` for MCP tools.
- `kiro-cli agent validate` checks JSON types only; it accepts tool references and capabilities that do not exist.
