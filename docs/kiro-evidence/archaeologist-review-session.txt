## Evidence Summary

### Defect found

**Defect:** `SummonRequestSchema` in `src/server.ts` validates `startLine` and `endLine` independently (`min(1)`) but never checks that `endLine >= startLine`, so a request with `startLine: 100, endLine: 1` passes the 400-level input guard and reaches `buildLedger`, which then calls `git blame -L100,1` — an inverted range that git rejects with a non-zero exit, producing an unintended 422 (`GIT_ERROR`) instead of the 400 (`VALIDATION_ERROR`) that **R9.2** requires.

**Introducing commit:** the record is silent — git tools are permission-gated in this session and I cannot cite a SHA. The defect is confirmed present in the current file.

**File and line:** `src/server.ts`, line ~87

```ts
startLine: z.number().int().min(1),
endLine: z.number().int().min(1),   // ← missing cross-field check
```

**Requirement broken:** Evidence-Ledger spec **R9.2** — *"Line range `start` and `end` SHALL be positive integers with `start <= end`… inputs outside these bounds SHALL be rejected"* — combined with Ghost-Verifier spec **R7.5** — *"On validation failure (bad input), `/api/summon` SHALL respond with HTTP 400 and `{ error: string; code: "VALIDATION_ERROR" }`"*.

The `LedgerInputSchema` in `src/evidence/ledger.input.ts` already has the correct `superRefine` guard (lines 34–42), so the fix is a one-liner in `server.ts`: add `.superRefine` to `SummonRequestSchema` mirroring what `ledger.input.ts` already does, or drop `SummonRequestSchema` entirely and use `LedgerInputSchema` directly:

```ts
// Option A — add superRefine to the existing SummonRequestSchema in server.ts
const SummonRequestSchema = z.object({ ... }).superRefine((val, ctx) => {
  if (val.endLine < val.startLine) {
    ctx.addIssue({
      code: z.ZodIssueCode.custom,
      path: ['endLine'],
      message: `endLine (${val.endLine}) must be >= startLine (${val.startLine})`,
    });
  }
});

// Option B (cleaner) — replace SummonRequestSchema with LedgerInputSchema
// and pass parsed.data directly to buildLedger (the shapes are already identical)
```

Option B is preferable because it removes schema duplication and ensures `server.ts` and `ledger.ts` can never diverge on input rules again.
