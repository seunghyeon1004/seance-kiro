Decisions already made (write them as requirements, reasoning in "Why"):
A. Hero copy: keep the headline; the lede gains one sentence saying every claim is checked against the commits and invented ones are struck out. Replace "any line of code" wording that overclaims (public GitHub repos, default branch, recent history). The hero must still fit 1280x800 without scrolling (ui-spooky.md).
B. The line in question: /api/summon returns `lines: [{ n, text }]`, the selected range read from the repository at HEAD (at most 40 lines, each cut to 400 chars), and `persona: { author }` (the most frequent ledger author, the same rule buildPrompt uses, exported from one place). The page shows the lines above the crypt under "The line in question", and names the ghost from `persona.author`, never from the model's `voice` string.
C. Guided path: after a summon, the talk column shows a three-step guide, each step one click:
   1. "Ask the ghost": question chips that submit immediately. For `crypt`: "Why is there a three second wait here?", "Who touched this line last, and why?", "Is it safe to delete the wait?". For `possessed`: "Can I delete this wait?", "Why does the wait exist?", "Who changed this?". For any other repo: "Why does this line exist?", "What would break if I removed it?".
   2. "Try to fool the ward": three buttons that send a planted claim immediately through /api/ward (invent a citation, misquote a real commit, blame the wrong author), reusing the existing presets. The manual form stays available below in the existing details element.
   3. "Run the exorcism".
   Each step shows a text marker when done ("done"), not colour alone. The guide is a list with real buttons, keyboard reachable in order, and does not trap focus. The ask textarea stays for free questions and is no longer `required` blocked silently: an empty submit shows an inline message.
D. Planted claims are the visitor's, not the ghost's: they do not change the "N of M claims verified this séance" counter or the candle, and their turn is labelled "Planted by you". A new summon resets the counter text, the ghost name, the last report and the guide.
E. Sleepy host: on page load the page calls GET /api/health (which now also returns `model: boolean` (a key is configured or fixture mode is on) and `samples: string[]` of built samples). `api()` retries network failures and 502/503/504 responses that are not our own JSON error (no `code` field) up to 3 times with 2 s, 5 s, 10 s waits, showing "Waking the spirits. The free server sleeps when idle; this can take up to a minute." in the relevant status region. Our own JSON errors are never retried. POSTs are retried only in that proxy/network case.
F. Model failures are mapped, never leaked: Anthropic API errors by status (401/403/404 -> 503 MODEL_CONFIG "The ghost cannot be reached: the server's model key or model name is wrong."; 429/529/5xx -> 503 MODEL_BUSY "The spirits are busy. Try again in a minute."); timeouts detected reliably (the SDK's APIUserAbortError or an aborted signal -> 503 TIMEOUT "The ghost took too long to answer."); schema failures -> 503 LLM_ERROR with a fixed sentence, details only in the server log; plan mode gets its own timeout LLM_PLAN_TIMEOUT_MS (default 90000). Missing key -> 503 CONFIG_ERROR "The ghost cannot speak on this server (no model key). The crypt and the ward still work."
G. Recorded answers when the model is unavailable: for the sample repos and the chip questions in C.1, the repository ships recorded model answers (recorded from real model calls by a script, never hand-written; directory `recordings/`, keyed by a hash of sample name + file + line range + question). When /api/ask fails with MODEL_CONFIG, MODEL_BUSY, TIMEOUT, CONFIG_ERROR or the daily cap, and a recording exists for that exact sample and question, the server returns the recording run through the live verifier against the current ledger, with `recorded: true`. The page labels it: "A recorded answer (the model is resting). The ward checked it again just now." Recorded answers never bypass the ward, never count against the daily cap, and are never used for non-sample repos or free-typed questions. The same for /api/exorcise on the two samples (one recorded plan each). The recording script and its README say a human with a real key runs it.
H. Honest empty and failed history: a failed or timed-out `git log -L` is an error (422 with a fixed sentence), not "0 commits"; a range with truly no history shows "No commits touched these lines." inside the crypt panel; a clone that hit the 100-commit depth sets `shallow: true` in the summon response and the crypt says "Only the most recent 100 commits were read. Older history is not in the crypt."
I. GitHub URLs as people paste them: a pure function `normaliseRepoInput(text)` in public/app.js (tested by extraction like test/ui/pbt/ui.pbt.ts does) that accepts trailing slashes, `.git`, `www.`, `http://`, `github.com/o/r` without scheme, and `/blob/<ref>/<path>#L10-L20` or `/tree/<ref>/<path>` URLs, returning `{ repoUrl, file?, startLine?, endLine?, note? }`; a blob URL fills the file and line fields; the note says the default branch is read. A leading `/` in the file field is stripped. The server's allowlist regex does not change.
