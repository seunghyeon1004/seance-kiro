## 1. Cold start

**[High] The page gives no warning about the wake-up wait.** SUSPECTED, based on how Render's free plan generally behaves. The container sleeps after about 15 minutes idle. Waking it takes Render's boot time plus `npm start` (package.json:15), which starts two npm processes, runs `make-crypt.sh` (about 10 commits), then compiles TypeScript at load time with tsx, all on a 0.1 CPU free instance. Until that finishes, the judge sees a blank tab or Render's own waiting page.
- Smallest fix: do the work at image build time. Add `RUN npm run crypt` to the Dockerfile after `COPY` (Dockerfile:6), so startup no longer runs a shell script and git. The crypt's hashes come out the same every time because every date and author is fixed in `make-crypt.sh`. Going further, compile with `tsc` at build time and use `CMD ["node", "dist/server.js"]`, so neither npm nor tsx runs at startup.

**[Medium] If the tab was opened earlier, the first click looks frozen or shows a code.** SUSPECTED. If the container went to sleep while the page stayed open, the Summon POST either hangs while it wakes or gets Render's HTML error page. `api()` (app.js:47-63) has no timeout and no retry. For a non-JSON reply it shows "The request failed (502)." The "Gathering evidence…" text (app.js:126) never changes.
- Fix: in `api()`, retry 502/503/504 and network errors two or three times with backoff, and change the status text to "Waking the spirits (the free server sleeps), up to a minute…". Optionally, `fetch('/api/health')` on page load so the container starts waking while the judge reads.

**[Low] The health check works but says nothing about the model.** CONFIRMED. render.yaml:6 points at `/api/health`, which returns `{status:'ok'}` (server.ts:242). It does not say whether a model key is set. The Dockerfile `HEALTHCHECK` (Dockerfile:9) is probably ignored by Render (SUSPECTED).
- Fix: add `model: Boolean(process.env.ANTHROPIC_API_KEY)` to the response, so the UI can say up front that only the ward demo will work.

## 5. Trying their own repo

CONFIRMED from the URL check (server.ts:89, also ledger.input.ts:7 and git.ts:454): `^https://github\.com/[\w.-]+/[\w.-]+(\.git)?$`.
- `https://github.com/o/r` and `…/r.git`: accepted.
- `…/r/` (trailing slash), `…/tree/main/src`, `…/blob/main/src/x.ts#L10-L20`, `http://…`, `www.github.com`: **400 "remote URLs must be https://github.com/<owner>/<repo>"**. That is recoverable, but a judge who pastes from the address bar will hit it. **[High]**
  - Smallest fix: normalize the URL in `validate()` (app.js). Strip the trailing `/` and `.git`, and when the URL contains `/blob/<ref>/<path>#Lx-Ly`, split it into the File and line fields. github.ts:34 already has a looser regex for this. Note that the ref is ignored: blame always runs on the default branch HEAD, which is worth one line of help text.
- `github.com/o/r` without the scheme: "Use the sample crypt or a https://github.com/<owner>/<repo> URL" (server.ts:171). Acceptable.
- A file path with a leading `/`: SUSPECTED git error with raw stderr. Fix: strip leading `/` in `validate()`.
- **[High] Big or active repo, history cut at 100 commits.** The clone is `--filter=blob:none --depth 100` (git.ts:546). The depth is CONFIRMED; the effects are SUSPECTED. In an active repo, 100 commits may be only weeks of history. The shallow boundary commit then looks like the commit that *added* the line, the real "why" commit is missing, and the ghost answers confidently from the wrong commit. Nothing on the page says the history was cut (`truncated` only reflects the 50-item cap, ledger.ts:33).
  - Fix: drop `--depth` (blob:none already keeps the history cheap), or at least flag a shallow clone in the response and show "history cut at 100 commits".
- **Time and feedback.** CONFIRMED caps: clone ≤30 s (git.ts:449), then blame, `log -L`, and two git calls per commit for up to 50 commits, one after another, each ≤10 s. On a blobless clone each call also downloads file contents on demand (SUSPECTED to be slow on Render free). Feedback is a fixed "Gathering evidence…" with no elapsed time or stage.
  - Fix: show an elapsed-seconds counter plus "A GitHub repo takes 10–60 s" in `#summon-status`.

## Ranked top eight

1. **Model failures all become "An unexpected error occurred".** Timeouts (abort check misses the SDK error), 529 overloaded, bad key (llm.ts:187, 196 → server.ts:156). Map `APIUserAbortError` and `APIError.status` to clear 503 messages.
2. **The default path shows no rejection.** Add a guided strip after summon: question chip, then "Try to fool it" and "Misquote a real commit" one-click buttons. Or at least open the plant `<details>` and move it above the ask form (index.html:192).
3. **The judge never sees the code being investigated.** Return the selected lines from `/api/summon` and show them above the crypt.
4. **Cold start with no feedback.** Build the crypt (and ideally compile the JS) at image build time. Add retry with backoff on 502/503/network errors in `api()`, a "waking the server" message, and a health ping on page load.
5. **Pasted GitHub URLs are rejected.** Normalize trailing slashes and `/tree/…`/`/blob/…#L…` URLs in `validate()`, filling the file and line fields.
6. **Silent empty ledger and shallow history give confidently wrong results.** Stop swallowing `log -L` errors (git.ts:291), drop or flag `--depth 100` (git.ts:546), and show the "no history" message in the séance panel (app.js:142).
7. **The exorcism will likely time out, and model errors show raw Zod JSON.** Use a longer timeout for plan mode (llm.ts:79), retry plan validation, and never send `parsed.error.message` to the client (plan.ts:87).
8. **The ward demo can dead-end.** Handle `SESSION_NOT_FOUND` in the plant handler (app.js:412). Leave planted claims out of the session counter and candle (app.js:293, 305). Reword "sha7 … not found in ledger" in plain language.
