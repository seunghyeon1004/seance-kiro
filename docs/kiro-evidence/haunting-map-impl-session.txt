## Where I departed from design.md
- **Synchronous throw guard.** `buildLedger` wraps the reader start in `try`/`catch` as well as `.catch`. Without it, a reader that throws synchronously failed the summon. A test confirmed that, and the test fails again if the guard is removed.
- **`wholeFileRange(n)`** is exported from `ledger.ts` so the HM11 property test can check the range rule directly.
- **Schema layout.** I exported `LineRangeSchema`. `LedgerResultSchema` reaches the map schemas through `z.lazy`, because they are declared later in the file.
- **Imports.** Design §5.1 says `haunting.ts` imports only `isSuspicious`. It also imports zod (for the parser's record schema) and some types from `schema.ts`. It is still pure: no clock, environment, filesystem, randomness or `localeCompare`.
- **Call spy.** The "exactly two git calls" spy wraps the real execa instead of `runGit`, because calls inside the same ESM module can't be intercepted. Real git still runs.
- **Order of work.** In T2 and T3 I wrote the git helpers just before their tests. The tests still failed first, because the reader and `buildLedger` support didn't exist yet.
- **Session ledger.** Following design §6.3, the stored ledger has no `haunting` key, but it now carries `range`. The items and prompts are identical to a ledger built without the map.
